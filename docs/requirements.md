# 要件定義書（簡易版）：もくもく会ボード

## 1. 何を作るか

POSSE の仲間どうしで「もくもく会（集まって各自勉強する会）」を開き、参加者を集めるための Web アプリ。

**困っていること**
- 勉強会の告知が Slack に流れてしまい、いつ・どこで・誰が来るのかが分からない
- 定員がある会で、何人集まっているかを主催者が手で数えている

**このアプリでできるようになること**
- これから開かれる会を一覧で見られる
- 誰でも会を開ける（告知できる）
- 会の詳細を見て、参加・キャンセルができる。定員を超えて参加できない

## 2. 前提

- 技術：PHP（フレームワークなし）＋ MySQL ＋ HTML/CSS/JavaScript
- ログイン機能は作らない。ヘッダーの「操作ユーザー」で、誰として操作するかを切り替える（`current_user()` で取れる）
- テーブル・初期データは `db/init.sql` に用意済み。見た目は `src/assets/style.css` に用意済み
- 画面の見た目は `docs/mockup/`（起動後は http://localhost:8080/mockup/ ）を正とする

## 3. 画面一覧と担当

3人チームで、1人1画面を担当する。**どの画面も、画面（HTML）・PHP・SQL の 3 つを全部触る。**

| # | 画面 | ファイル | 主に使う SQL | 担当 |
|---|---|---|---|---|
| ① | 会の一覧 | `src/index.php` | `SELECT` ＋ `LEFT JOIN` ＋ `GROUP BY`（参加人数を数える） | Aさん |
| ② | 会をつくる | `src/new.php` | `INSERT`（入力チェックしてから保存） | Bさん |
| ③ | 会の詳細・参加 | `src/detail.php` | `SELECT` ＋ `INSERT` / `DELETE`（参加・キャンセル） | Cさん |

画面のつながり：① の「会をつくる」→ ② → 保存すると ③ へ。① のカードを押す → ③。③ の「一覧へ戻る」→ ①。

## 4. データ

| テーブル | 中身 | 主な列 |
|---|---|---|
| `users` | 操作ユーザー（5人） | `id`, `name` |
| `events` | もくもく会 | `id`, `organizer_id`（主催者）, `title`, `description`, `place`, `starts_at`（開催日時）, `capacity`（定員）, `created_at` |
| `participants` | 参加登録 | `id`, `event_id`, `user_id`, `created_at`。`(event_id, user_id)` は UNIQUE |

- 参加人数は `events` に列を持たず、`participants` の行数を数えて出す
- 主催者は参加者に含めない（主催者が自分の会に参加ボタンを押すことはない）

## 5. 画面ごとの機能要件

各画面の「受け入れ条件」がすべて満たせたら、その画面は完成。PR を出す前に自分で 1 つずつ確かめる。

### ① 会の一覧（`index.php`）

**表示するもの**
- これから開かれる会（`starts_at` が今より後）を、開催日時が近い順に並べる
- 各カードに：タイトル、開催日時、場所、主催者名、「参加人数 / 定員」
- 満員の会には「満員」バッジを付ける

**受け入れ条件**
- [ ] 終わった会（初期データの「Git 入門ハンズオン」）が表示されない
- [ ] 開催日時が近い順に並んでいる
- [ ] 参加者が 0 人の会（初期データの「LP 模写会」）も「0 / 5」で表示される（`INNER JOIN` だと消えてしまう）
- [ ] 「SQL 演習会」に「満員」バッジが付いている
- [ ] カードを押すと、その会の `detail.php?id=…` に移動する
- [ ] 会が 1 件もないときは「これから開かれる会はありません」と表示する

### ② 会をつくる（`new.php`）

**入力項目**：タイトル、開催日時、場所、定員、説明（すべて必須）

**ルール**
- タイトルは 100 文字以内、場所は 100 文字以内
- 開催日時は今より後
- 定員は 1〜50 の整数
- 主催者は、いま操作しているユーザー

**受け入れ条件**
- [ ] GET で開くとフォームが表示される
- [ ] 正しく入力して送信すると `events` に 1 行増え、作った会の `detail.php?id=…` に移動する
- [ ] 空の項目があると保存されず、項目ごとにエラーメッセージが出る
- [ ] エラーで戻ってきたとき、入力した内容が消えていない
- [ ] 過去の日時、定員 0 や 51 は保存されない
- [ ] 送信後にブラウザを再読み込みしても、同じ会が 2 件できない（保存後はリダイレクトする）

### ③ 会の詳細・参加（`detail.php?id=…`）

**表示するもの**
- 会の情報：タイトル、開催日時、場所、主催者名、説明、「参加人数 / 定員」
- 参加者の名前の一覧（申し込みが早い順）。0 人なら「まだ参加者はいません」
- 操作ユーザーの状態に合わせたボタン

| 操作ユーザーの状態 | 出すもの |
|---|---|
| 主催者 | 「あなたが主催する会です」（ボタンなし） |
| 参加済み | 「キャンセルする」ボタン |
| 未参加・空きあり | 「参加する」ボタン |
| 未参加・満員 | 「満員です」（押せない） |

**受け入れ条件**
- [ ] 「参加する」を押すと `participants` に 1 行増え、参加者一覧に自分の名前が出る
- [ ] 「キャンセルする」を押すと自分の行が消える
- [ ] 同じ人が 2 回参加できない（2 回押しても、別タブから送っても 1 行のまま）
- [ ] 満員の会には参加できない（ボタンを消すだけでなく、PHP 側でも人数を確かめる）
- [ ] 存在しない id（`detail.php?id=999`）では「会が見つかりません」と表示する
- [ ] 参加・キャンセルの後に再読み込みしても、もう一度送信されない（処理後はリダイレクトする）

## 6. 全画面共通のルール

- 画面に出す文字は必ず `h()` を通す（XSS 対策）
- SQL に値を入れるときは必ずプリペアドステートメント（`prepare` → `execute`）を使う
- 日時は `2026/10/29（木）19:00` の形で表示する（`format_datetime()` を使う）
- 共通部分（ヘッダー・フッター）は `partials/` を `require` して使う。自分の担当ファイル以外は、チームに相談してから変える

## 7. 今回やらないこと

- ログイン・ユーザー登録
- 会の編集・削除
- 画像のアップロード
- 検索・ページ送り
