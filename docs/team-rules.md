# チームの取り決め（模範解答）

要件定義書は「画面ごと」の要件しか決めていません。
**画面と画面がつながるところ**で決めておかないと食い違うことを、実装を始める前にチームで話し合って、ここに書きます。

考えるヒント：
- ある画面でつくった・変えたデータを、別の画面はどう表示する？どう数える？
- ある画面から別の画面へ移るとき、何を渡す？
- 同じものを複数の画面で表示するとき、見た目はそろっている？

| # | 決めたこと | 内容 | 関係する画面 |
|---|---|---|---|
| 例 | ① のカードから ③ へ移るときの URL | `detail.php?id=会の id` | ①・③ |
| 1 | ② で保存したあとの移動先 | つくった会の `detail.php?id=…`（つくった直後に中身を確かめられるように） | ②・③ |
| 2 | 「満員」の判定 | `participants` の行数 `>=` `capacity`。主催者は `participants` に入らないので数えない（③ で主催者は参加できない） | ①・③ |
| 3 | 「これからの会」の範囲 | `starts_at > NOW()`（時刻まで見る。今日でも始まった会は出さない）。② の「過去の会はつくれない」も同じ基準で、今より前の日時はエラー | ①・② |
| 4 | 日時の形 | `2026/10/29（木）19:00`。全画面で同じ関数を使うため、`lib/db.php` に `format_datetime()` を追加（チームに相談して共通部品を変更） | ①・③ |

> 決めたことを変えたくなったら、変える前にチームに伝えて、この表も直す。
